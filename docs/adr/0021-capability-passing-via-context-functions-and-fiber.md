# 21. Capability passing via context functions and FiberRef; the environment is reserved for service wiring

- Status: Accepted

## Context
The tracked-capabilities design (issue #716, after Odersky's *Tracked Capabilities for Safer Agents* and lampepfl/tacit) needs a mechanism for granting and tracking capabilities (git write, push, exec, coder, declassify) through flow code. Two candidate mechanisms exist in ZIO-flavoured Scala 3: the ZIO environment (`ZIO[GitWriteCap & ExecCap, E, A]`, granted by `provide`) and context parameters (`(using Caps.GitWrite)`, granted by entry-point context arguments). The question was re-examined deliberately — including whether the library should instead adopt zio-direct, zio-blocks, or switch to Ox outright — because a published ZIO library whose safety feature is not expressed in ZIO's "native" mechanism looked like an idiom risk for adoption.

## Decision
Capabilities are passed as context parameters (unforgeable witness traits with `private[llm4zio]` constructors, entering scope only as entry-point context arguments) and enforced at runtime by an ambient `FiberRef[Grants]` scoped with `locallyWith` intersection. The ZIO environment is reserved for what post-2.0 ZIO uses it for: coarse service wiring at application edges (the embedder surface). Effect composition stays ordinary monadic ZIO — no macro direct-style syntax.

Two facts are dispositive. First, fine-grained capabilities-in-R is the *pre-ZIO-2* idiom: ZIO 2's flagship migration removed Clock/Console/System/Random from the environment precisely because such ambient, low-level requirements "polluted the environment type" and did not fit the service pattern; ZIO 2 carries them on the runtime's FiberRefs — the very shape this design uses. Second, the source material's own mechanism is context parameters: tacit declares capabilities as `using` params, and capture checking is built on context functions, so witnesses are a transliteration of the paper where R-composition would be a homegrown variant. A third, structural reason: capabilities-in-R forces R-polymorphism through every flow-layer HOF (`implementTaskLoop`, `stage`, `Chat`, `fixLoop`), abandoning the deliberately monomorphic `IO[FlowError, A]` surface, whereas context parameters resolve lexically and leave every signature untouched.

## Alternatives considered
Capabilities in the ZIO environment — rejected: recreates pre-2.0 environment pollution, infects every higher-order signature with R-polymorphism, and its real benefits (inference-driven requirement accumulation, `provideSome` attenuation, scaladoc legibility) do not outweigh; requirement accumulation by inference is also invisible in untyped `.sc` scripts, which is the wrong grain for a safety feature. Switching the library to Ox — rejected: llm4zio-on-Ox *is* orca, which exists and is maintained; the move would abandon the library's niche (ADR 0001) and, per Ox's own comparison, trade away typed error tracking, compiler-enforced resource safety and robust interruption. zio-direct for direct-style syntax — rejected: dormant at 1.0.0-RC7 for years, and it addresses effect *syntax*, which was never the mechanism question. zio-blocks — not adopted, kept on a watchlist: development-stage, but its effect-agnostic design and type-level `Scope` corroborate the direction away from R-as-capabilities; revisit for `Classified`/`Pack` concerns when it stabilises.

## Consequences
The flow layer keeps its monomorphic direct-reading surface while gaining compile-time capability tracking (`flow.restricted[C]`) and runtime scoping (`restricted { }` ≈ the `logAnnotate`/FiberRef-locally pattern ZIO users already know). The idiom obligation moves to the embedder surface: because flows do not showcase ZLayer, the library must offer a first-class service-pattern bridge for ZIO application developers — `FlowContext` assembly via ZLayer, a `Grants`-accepting `Llm4zio.run`, and a "llm4zio for ZIO developers" concept map — tracked as the embedder-bridge workstream in the tracked-capabilities plan. Contributors should not add fine-grained requirement types to `R`; new ambient, cross-cutting state follows the FiberRef pattern.
